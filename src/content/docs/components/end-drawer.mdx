---
title: EndDrawer
description: Configure content that enters from the logical end edge of DrawerLayout.
---

`EndDrawer` is the end-side counterpart to `StartDrawer`.

## Control the end edge

```cpp fragment
EndDrawer(ToolsPane())
    .Open(tools_open)
    .OnOpenChanged([tools_open](bool open) {
      tools_open = open;
    })
```

The application owns the open value. The component emits `DrawerEvents::OpenChanged` after gestures, outside presses, or other drawer interactions request a transition. The active `DrawerStyle` controls modal and persistent presentation.

## Preserve content semantics

`EndDrawer` is a structural wrapper and preserves the semantic order and meaning of its content instead of publishing a separate control role.

## API

- `EndDrawer(View content)`.
- `Open(bool)` and `Open(State<bool>)`.
- `OnOpenChanged(handler)`.

See [DrawerLayout](../drawer-layout/) and [StartDrawer](../start-drawer/).

## Independent trailing content

Give this side its own boolean State, defaulting to false, rather than sharing the start drawer's open flag. It remains modal in Medium and prefers inline in Expanded, subject to the actual width budget. An inline end drawer is visible regardless of its modal Open value; [DrawerLayout](/docs/components/drawer-layout/#responsive-policy-and-controlled-modal-state) defines the fallback order when both sides cannot fit.

The content is one View, often a Column or ScrollView, and it retains its own application state. `.Open` and `.OnOpenChanged` are rvalue-qualified configuration methods chained on the declaration. `OnOpenChanged(bool)` requests a change; no implicit assignment to a passed State is performed.
