Toasts live in the window layer stack rather than the application layout tree. Obtain the window-scoped handle and show a message:

## Show transient feedback

```cpp fragment
auto toast = UseToast();

Button("Save").OnClick([toast] {
  toast.Show("Changes saved");
})
```

`ToastHandle::Show` accepts `StringVariant` and `ToastOptions`; the default duration is two seconds. It returns a `LayerId` that can be dismissed early with `Dismiss`.

## Theme and announcement

The captured environment determines theme and localized resources. `ToastStyle` controls placement, viewport padding, surface, typography, shadow, width, and optional motion. Toasts announce transient status through live-region semantics without taking focus.

## API

- `UseToast()` returns `ToastHandle` for the current window.
- `Show(StringVariant, ToastOptions = {}) -> LayerId`.
- `Dismiss(LayerId) -> bool`.
- `ToastOptions::duration` is measured in seconds.
- `ToastStyle` and `VerticalPlacement` define theme presentation.

See [Presentation](../../guides/presentation/) for layer lifetime and theming.

## Request identity and limits

Each `Show` creates an independent toast; it does not replace the previous message. Save the returned `LayerId` only if an event needs to dismiss that specific toast early. `Dismiss(id)` returns false for a stale identifier. Duration must be finite and nonnegative; zero is an immediate-expiry request, not persistent feedback.

The handle captures the Environment when `UseToast()` runs. Capture the handle by value in an event and call it on the UI thread. Do not invoke Show directly during composition, where recomposition could emit duplicate notifications.

## `ToastStyle` fields

`background`, `text_style`, `padding`, `shadow`, and `corner_radii` describe the message surface. `minimum_height` and `maximum_width` bound its geometry; `viewport_padding` leaves space at safe edges. `placement` is Top, Center, or Bottom. `motion` is optional `PresentationMotion`, with `std::nullopt` disabling transitions.

Use [SnackBar](/docs/components/snack-bar/) for an action or replacement-style feedback. Do not put essential errors only in an expiring toast; retain them near the affected form or operation as well.
