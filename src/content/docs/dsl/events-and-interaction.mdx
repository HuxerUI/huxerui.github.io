Events describe semantic output from a `View`.
Handlers are bound declaratively and replaced when the node recomposes.

## Convenience events

```cpp fragment
Button("Save").OnClick([] {
  SaveDocument();
})
```

Controls add type-safe conveniences for their primary output:

```cpp fragment
Checkbox("Autosave", autosave)
    .OnChanged([autosave](bool checked) {
      autosave = checked;
    })

Slider(volume)
    .Range(0.0F, 100.0F)
    .Step(1.0F)
    .OnChanged([volume](float next) {
      volume = next;
    })
```

The convenience methods delegate to the same typed event keys used by `.On<Key>(...)`.

## Built-in event families

| Event family | Keys |
|---|---|
| `ViewEvents` | `Click`, pointer down/move/up/cancel, `FocusChanged`, key down/up, `BackRequested` |
| `ToggleEvents` | `Changed(bool)` |
| `SliderEvents` | `Changed(float)` |
| `SegmentedButtonEvents` | `Changed(std::size_t)` |
| `TabsEvents` | `Changed(std::size_t)` |
| `NavigationEvents` | `Changed(std::size_t)` |
| `DrawerEvents` | `OpenChanged(bool)` |
| `TextFieldEvents` | `Changed(const TextEditingValue&)`, `Submitted` |

Bind a less common event explicitly:

```cpp fragment
View content = Canvas(DrawScene)
    .On<ViewEvents::Pointer>([](const PointerEvent& event) {
      UpdatePointer(event.position);
    });
```

`ViewEvents::Pointer` positions are window-local logical coordinates; gesture payloads expose their documented node-local positions instead.
`PointerEvent` also reports its type, pointer identifier, device kind, buttons, and modifiers; use `MultiTapGesture` for repeated taps.

## Keyboard and Back

`KeyEvent` reports `Down` or `Up`, a normalized `Key`, text, modifier flags, and repeat state.
Use `Focusable` when a custom node needs keyboard focus.

`ViewEvents::BackRequested` is the simple semantic event for a committed Back request.
Navigation and platform integration additionally use phased `BackEvent` values internally for predictive transitions.

## Disabled input

Apply `Enabled(false)` to remove semantic activation and disabled controls from normal interaction:

```cpp fragment
Button("Delete")
    .OnClick(DeleteSelection)
    .With(Enabled(has_selection))
```

Themes resolve disabled visuals from the same interaction state.

## Custom component events

Define a key by inheriting `Event<Result(Arguments...)>`:

```cpp fragment
struct SearchRequested : Event<void(std::string)> {};
```

A scoped component obtains an emitter and emits through the key:

```cpp fragment
[[huxerui::composable]]
View SearchBox() {
  auto value = UseState(TextEditingValue{});
  auto events = UseEvents();

  return Row {
    TextField(value).OnChanged([value](const TextEditingValue& next) {
      value = next;
    }),
    Button("Search").OnClick([events, value] {
      events.Emit<SearchRequested>(value->text);
    }),
  };
}
```

The caller binds the custom key exactly like a built-in event:

```cpp fragment
SearchBox().On<SearchRequested>([](std::string query) {
  BeginSearch(std::move(query));
})
```

`EventEmitter` is a weak connection to the component's current event hub.
`IsConnected()` reports whether the declaring scope still has a live hub.

## Focus a mounted control

Bind a `ViewHandle` to the editor and request focus from an event. The state update and focus request can happen directly in that event.

```cpp compile="request-view-focus"
#include <huxerui/huxerui.h>

using namespace huxerui;

[[huxerui::composable]]
View SearchForm() {
  auto query = UseState(TextEditingValue{});
  auto editor = UseViewHandle();

  return Column {
    TextField(query)
        .Label("Search")
        .OnChanged([query](const TextEditingValue& next) { query = next; })
        .With(editor),
    Button("Focus search").OnClick([editor] { editor.RequestFocus(); }),
  }.With(Spacing(8.0F));
}
```

The same handle can anchor a [Popup](/docs/components/popup/) or supply a [scene transition origin](/docs/guides/animation/#run-a-scene-transition). See [mounted view handles](/docs/reference/modifier/#mounted-view-handles) for lifetime and focus eligibility.

## Interaction visuals

Hover, focus, focus-visible, pressed, and enabled are runtime interaction facts.
Themes translate them into `Indication`, focus rings, control colors, and animation without requiring a separate state variable for each event.

Use [gesture modifiers](/docs/guides/gestures/) for recognition, raw pointer events for observation, and result-bearing key events for explicit keyboard policy. Do not reimplement built-in activation.
