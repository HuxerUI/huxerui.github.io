Linux uses GTK 4.14 or later for windows, event dispatch, IME, clipboard, and GSK presentation. Pango owns text layout; Cairo nodes replay ordinary paint while GDK texture nodes compose ExternalTexture frames in the same snapshot. GTK selects its display backend; the shared application does not implement X11 or Wayland protocols.

```bash
huxerui setup linux
huxerui run linux
```

## Dependencies and services

GTK 4, libepoxy, GIO, and libsoup 3 resolve through pkg-config and remain distribution-owned dependencies. Use the SDK and system dependency versions required by the selected release rather than carrying a second vendored desktop stack.

Keep UI work on the GTK main context. GtkIMContext handles composition and surrounding text; the platform boundary converts scale and input geometry. File pickers use the platform/portal integration available to the desktop. HTTP uses libsoup.

## Graphics and integration

`<huxerui/linux/external_texture.h>` provides PixelTexture, GlTexture, and GdkTexture. GlTexture snapshots a mutable producer texture; GdkTexture requires immutable backing content. Consult the [texture guide](/docs/guides/external-texture/) for ownership.

System tray presentation depends on the desktop's status-item host. Query availability and keep a visible-window fallback. External file drops use FileReference and share the [file reception API](/docs/reference/file/#external-file-drops).

The pinned revision has no public Linux PlatformView factory or repository-owned semantic accessibility bridge. GTK ownership alone does not supply those shared-component contracts.

## Verification boundary

Linux application runtime behavior requires the matching GTK desktop environment. The website's Web and public-header checks do not certify Linux IME, display-server integration, graphics drivers, tray behavior, or assistive technology.

## System capability boundaries

Official Linux SDK binaries require glibc 2.38 or later alongside the documented GTK and system dependencies. Builds on Ubuntu 24.04 do not establish validation on every distribution meeting that baseline. The shared local-notification capability is currently unavailable.

See [Local notifications](/docs/guides/local-notifications/) for shared usage and platform configuration, and [System API](/docs/reference/system/) for exact contracts.

## Application and window ownership

The application Runtime shares services, ordinary tasks and observable State across its UI attachments. Each UiWindow owns composition, focus, layers and presentation. This desktop backend implements OpenWindow; each created window has independent UI state and a fresh root Environment. See [Application and windows](/docs/guides/application-and-windows/).

System-theme preference is window-local and observed through UseSystemThemeBrightness. Custom font families retain application-supplied static data; test fallback and platform text scaling with localized content. Native runtime/device validation remains separate from website contract checks.
