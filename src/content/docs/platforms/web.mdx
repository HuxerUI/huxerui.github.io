Web builds use Emscripten and link the HuxerUI static SDK library into a WebAssembly application.

```bash
huxerui setup web
huxerui run web
```

The browser UiWindow owns animation-frame scheduling, canvas presentation, DOM input and IME conversion, HTTP through browser networking, file capabilities, activation, and visibility lifecycle.
The pinned revision does not yet project the shared semantic tree into an accessible DOM tree; the render canvas and hidden text-input element are marked `aria-hidden`.

Use `<huxerui/web/navigation.h>` for `BrowserNavigationStack`, which synchronizes a typed `NavigationPath<Route>` with URL and browser back/forward history through an application codec. DOM-backed platform views are registered with `<huxerui/web/platform_registry.h>`; browser external texture sources use `<huxerui/web/external_texture.h>`.

Browser security policy governs network origins, file access, clipboard permission, autoplay, and external resources. A Web build cannot rely on native filesystem paths or unrestricted synchronous I/O.

Website CI builds every listed Web example at the pinned revision, but browser permissions and assistive-technology behavior still require environment-specific testing.

## System capability boundaries

Browser-selected file references use async streams. For writable persistent local paths, use the async write and close path so browser storage is synchronized. Writable random-access streams are available only where the local path does not require async persistence.

Asynchronous [clipboard operations](/docs/reference/text-and-input/#clipboard) can use text, HTML, and PNG in a secure context. Start them in the user action and handle denied or unsupported results. File-list clipboard access is unavailable.

Browser permission queries cover camera, microphone, and location where supported. Prompts for those features come from browser acquisition APIs. Browser notification authorization can be requested during an active user gesture. HuxerUI local notification delivery and BufferReference payload bridging remain unavailable.

See [Local notifications](/docs/guides/local-notifications/) for shared usage and platform configuration, and [System API](/docs/reference/system/) for exact contracts.

## Application and window ownership

The application Runtime shares services, ordinary tasks and observable State across its UI attachments. Each UiWindow owns composition, focus, layers and presentation. The browser backend does not expose programmatic native OpenWindow; separate demo sessions are independent applications. See [Application and windows](/docs/guides/application-and-windows/).

System-theme preference is window-local and observed through UseSystemThemeBrightness. Custom font families retain application-supplied static data; test fallback and platform text scaling with localized content. Native runtime/device validation remains separate from website contract checks.
