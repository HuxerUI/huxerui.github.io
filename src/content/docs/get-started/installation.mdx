HuxerUI ships as a relocatable SDK with the `huxerui` command-line tool, CMake packages, host code generators, built-in resources, and packaged platform artifacts.

## Requirements

For the CMake/SDK workflow, prepare:

- A C++20 compiler supported by the selected platform toolchain.
- CMake 3.20 or later.
- The HuxerUI SDK for the current development host.

Platform builds also require their platform SDK: Visual Studio on Windows, Xcode on Apple platforms, the Android SDK and NDK for Android, or Emscripten for Web.

## Build the documented revision

This manual follows the source commit shown beside each page title. New APIs can precede a public SDK release; the Downloads page reports released artifacts independently. Build the documented source revision when following these examples.

```bash
git clone https://github.com/HuxerUI/HuxerUI.git
git -C HuxerUI checkout 56eb5ab225997cffc83ce8f2736d1fd52c530b70
```

For a host-only CMake package, configure from a supported developer environment. On Windows use an MSVC Developer PowerShell with Ninja available; on macOS use Xcode command-line tools; Linux requires the GTK/system dependencies in its platform guide:

```bash
cmake -S HuxerUI -B build/huxerui -G Ninja -DCMAKE_BUILD_TYPE=Release -DHUXERUI_BUILD_SHARED=OFF -DHUXERUI_BUILD_STATIC=ON -DHUXERUI_BUILD_TESTS=OFF -DHUXERUI_BUILD_EXAMPLES=OFF
cmake --build build/huxerui --parallel 4
cmake --install build/huxerui --prefix build/huxerui-install
```

Point CMAKE_PREFIX_PATH to that install for a custom desktop CMake application, or use the source checkout directly through add_subdirectory as shown in [CMake integration](/docs/tooling/cmake/). A host install alone does not create Android/Web SDK artifacts.

For a complete SDK, the source repository provides scripts/package_sdk.ps1 and scripts/package_sdk.sh. They build target artifacts and require a complete Android/Java/Emscripten environment; macOS packaging also builds iOS with Xcode. Keep their build/output under a build directory. They do not bootstrap missing SDKs.

For a desktop module project use [C++ Modules and mcpp](/docs/tooling/cpp-modules-and-mcpp/), which has its own manifest/build rules and current C++23 template mode.

## Select an SDK

The CLI first honors an explicit `HUXERUI_HOME` and otherwise discovers the SDK relative to its own executable.
Set `HUXERUI_HOME` when you keep multiple SDKs or use a source checkout intentionally.

```powershell
$env:HUXERUI_HOME = "D:\Environment\HuxerUI"
$env:Path = "$env:HUXERUI_HOME\bin;$env:Path"
```

```bash
export HUXERUI_HOME=/opt/huxerui
export PATH="$HUXERUI_HOME/bin:$PATH"
```

## Diagnose the environment

Run the read-only doctor before creating or building an application:

```bash
huxerui doctor
```

Limit diagnosis to the platforms you plan to use:

```bash
huxerui doctor windows,web
```

`doctor` reports the selected SDK and missing external tools without installing or changing them.
Use `setup` for supported platform prerequisites that the CLI can acquire:

```bash
huxerui setup android,web
```

## Direct CMake consumers

Projects that do not use a generated application shell can locate the installed package directly:

```cmake
find_package(HuxerUI CONFIG REQUIRED)
target_link_libraries(my_target PRIVATE HuxerUI::huxerui_static)
```

Use `HuxerUI::huxerui` when the host platform and package use the shared library form.
Application projects should prefer `huxerui_add_app`, which also enables scope code generation and resource packaging.
