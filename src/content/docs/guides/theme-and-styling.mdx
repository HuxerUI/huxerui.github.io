---
title: Theme and styling
description: Apply inherited visual systems and customize component styles.
---

Theme is HuxerUI's visual specialization of `Environment`.
A generated application does not force a visual family; choose a built-in theme or provide an application `ThemeDefinition` when the product is ready to own that decision.

## Select a visual family

```cpp fragment
View App() {
  return MaterialTheme {Content()};
}
```

Built-in entry points include `MaterialTheme`, `MaterialDarkTheme`, `FlatTheme`, and `FlatDarkTheme`. Each accepts declarative View content; light-family overloads accepting `ThemeSpec` let applications replace tokens while retaining the component recipes for that family. The composable transform defers child composition so descendants see the provider. Enable code generation for these declarations.

Material and Flat are complete theme definitions rather than color presets.
They may resolve different geometry, interaction indication, menu separators, dialog placement, presentation motion, and typography from the same component intent.

## Customize theme tokens

```cpp fragment
View BrandedApp() {
  ThemeSpec spec = MaterialLightThemeSpec();
  spec.colors.primary = Color::Rgb(92, 61, 180);
  return MaterialTheme(spec, Content());
}
```

`ThemeSpec` groups color, typography, shape, spacing, elevation, motion, and interaction schemes. `ThemeDefinition` additionally owns component and presentation style resolvers. Use `UseTheme()` to read the resolved `ThemeSpec`; use `Theme(definition, content)` for a custom definition.

Start from `MaterialLightThemeSpec`, `MaterialDarkThemeSpec`, `FlatLightThemeSpec`, or `FlatDarkThemeSpec` when a branded theme should retain the corresponding component recipes.
Use a complete `ThemeDefinition` when the application needs its own style-resolution policy.

## Override one composition

Common modifiers can still override a particular view's background, foreground, border, shadow, opacity, transform, and indication. Prefer theme customization for repeated visual intent and modifiers for local composition. Component-specific style structures are documented in the [Theme API](../../reference/theme/).

Local modifiers apply to the declared node and do not rewrite its component recipe.
For example, a local `Background` can change one surface while `ButtonStyle` still owns button minimum size, typography, disabled state, and interaction visuals.

## Configure interaction visuals

`InteractionScheme` supplies the default `Indication`, `FocusRing`, and disabled opacity.
An `Indication` can animate focus, hover, and press layers and an optional ripple; layers support color, gradient, or image `VisualFill`, border, radii, placement, and enter/exit animation.

Keep interaction state in the runtime.
Do not introduce application `State<bool>` for hover or press only to select colors during composition.

## Style presentation surfaces

Dialog, BottomSheet, Menu, Popup, Toast, and navigation transitions resolve through theme-owned style structures.
This lets a Material, Flat, or application theme change placement and motion as well as color without changing call sites.

See the [Theme API](../../reference/theme/), [Modifiers](/docs/dsl/modifiers/), and [Presentation](/docs/guides/presentation/).

## Follow the host's light or dark preference

UseSystemThemeBrightness belongs to the current window. Application policy can choose System, Light or Dark; that policy does not require a new framework theme enum.

```cpp compile="system-theme-policy"
#include <huxerui/huxerui.h>

using namespace huxerui;

enum class AppearanceChoice { System, Light, Dark };

[[huxerui::composable]]
View AppearanceSettings() {
  auto choice = UseState(AppearanceChoice::System);
  const AppearanceChoice selected = choice;
  const auto system = UseSystemThemeBrightness();
  const bool dark = selected == AppearanceChoice::Dark ||
      (selected == AppearanceChoice::System && system == ThemeBrightness::Dark);
  const auto spec = dark ? MaterialDarkThemeSpec() : MaterialLightThemeSpec();
  return MaterialTheme(spec, Column {
    Text("Appearance", TextRole::Title),
    Row {
      Button("System").OnClick([choice] { choice = AppearanceChoice::System; }),
      Button("Light").OnClick([choice] { choice = AppearanceChoice::Light; }),
      Button("Dark").OnClick([choice] { choice = AppearanceChoice::Dark; }),
    }.With(Spacing(8.0F)),
  }.With(Padding(24.0F), Spacing(16.0F), Background(spec.colors.background)));
}
```

A system change recomposes subscribed scopes. The explicit Light/Dark choice remains authoritative until the user selects System again. ThemeSpec::brightness describes the chosen theme, not a request to change the OS.

Theme updates refresh open dialogs, sheets and transient presentation without recreating their controlled contents. A detached provider retains its last resolved palette. Use [scene transitions](/docs/guides/animation/#run-a-scene-transition) when the product wants an animated theme mutation; system-following policy itself does not start a scene animation.

Set TypographyScheme::family to a packaged FontFamily when the product owns its font. See [Fonts and typography](/docs/guides/fonts-and-typography/); changing only family should not replace role sizes or explicit per-view font choices.
