title: PlatformModule
description: Register typed services and choose a cross-language channel only when the integration needs one.
---

A PlatformModule gives a platform SDK capability a typed C++ interface. It does not have to inherit a framework class or route every call through string messages.

## A root-owned service

Define the shared interface, implement it in platform-selected source files, and register a factory in a root hook. The complete declaration below leaves `CreateDeviceInfo` to the platform implementation rather than pretending to return a real platform value:

```cpp compile="typed-platform-service"
#include <huxerui/huxerui.h>

#include <memory>
#include <string>

using namespace huxerui;

struct DeviceInfo {
  virtual ~DeviceInfo() = default;
  virtual std::string Model() const = 0;
};

std::shared_ptr<DeviceInfo> CreateDeviceInfo(PlatformAdapter& adapter);

void InstallDeviceInfo(RootContext& root) {
  root.RegisterPlatformModule<std::shared_ptr<DeviceInfo>>("app/device-info", CreateDeviceInfo);
  root.Provide<DeviceInfo>(root.OpenPlatformModule<std::shared_ptr<DeviceInfo>>("app/device-info"));
}

View App() {
  auto device = UseService<DeviceInfo>();
  return Text(device->Model());
}

AppOptions Options() {
  AppOptions options;
  options.root_hooks.push_back(InstallDeviceInfo);
  return options;
}

const Application application{App, Options()};
```

The service is shared for this Runtime/window, not a process-wide singleton. Keep platform handles in the implementation, respect its UI-thread and resource-lifetime rules, and report unavailable capabilities explicitly.

## Component-owned instances

Use the free `OpenPlatformModule<Module>()` only inside committed `Lifecycle` setup when an instance should follow a component's mount/dependency lifetime. Return a cleanup that closes or releases it. Opening during composition is rejected: composition may be retried and is not a safe place to create platform side effects.

Factories may accept an explicit options type through `RegisterPlatformModule<Module, Options>`. The open call must use the same registered types and case-sensitive name. Prefer an integration library's `Install...` and `Use...` helpers so applications do not repeat registration names.

## When a channel helps

Java or JavaScript objects may need asynchronous named methods and events. Wrap `PlatformChannel` in the same typed service interface rather than exposing payload parsing throughout application code.

```cpp fragment
channel.Invoke<double>("batteryLevel", std::monostate{},
    [level](PlatformResult<double> result) {
      if (const auto* value = std::get_if<double>(&result)) {
        level = *value;
      }
    });
```

The result type is explicit; primitive wire conversion is built in. Structured request/result types own static `Encode` and `Decode` operations. An event key supplies its `Event<...>` signature and stable `Name`; its structured value type owns conversion.

Keep the returned request identity if you need to cancel. Closing a channel affects its copies, invalidates pending work, detaches events, and disposes the platform instance. Completion is delivered at most once on the owning UI thread. Do not wait synchronously for it or assume that cancelled work still calls your completion.

## Capabilities are not byte strings

`PlatformPayload` can carry `std::shared_ptr<ExternalTexture>` and `FileReference` alongside ordinary values. Forward the complete encoded envelope, including its capability tables. Do not reduce a document-provider reference to a filesystem path or a live texture to an integer handle.

## Choose the boundary

- Use ordinary C++ for shared algorithms.
- Use a root service for coordinated per-window ownership.
- Register a PlatformModule for a platform implementation of that service.
- Use [PlatformView](/docs/guides/platform-view/) for an actual platform control.
- Use [ExternalTexture](/docs/guides/external-texture/) for changing pixels without platform-control input.

Test missing registration, exact options types, teardown during work, cancellation, late events, and thread delivery. See the [registry and channel reference](/docs/reference/platform-module/) for individual contracts.
