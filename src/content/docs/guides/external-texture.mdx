---
title: ExternalTexture
description: Publish live CPU or GPU frames without rebuilding the application tree.
---

An external texture is one shared producer identity. Platform-specific classes derive from `ExternalTexture`; pass their `std::shared_ptr` directly to `Image`. There is no separate source-to-handle conversion.

## Choose a producer

| Platform | Producer choices |
| --- | --- |
| Windows | `windows::PixelTexture` for copied CPU rows; `windows::D3D11Texture` for immutable shared GPU snapshots. |
| Android | `android::BitmapTexture`, `android::GlTexture`, or `android::SurfaceStreamTexture`. |
| iOS / macOS | `PixelBufferTexture` for Core Video frames; `MetalTexture` for GPU snapshots in the platform namespace. |
| Linux | `linux::PixelTexture`, `linux::GlTexture`, or `linux::GdkTexture`. |
| Web | `web::VideoFrameTexture` for a browser VideoFrame. |

Include the matching platform header explicitly. These producer types are not interchangeable across renderer backends.

## A software frame on Windows

This integration fragment receives an existing RGBA byte span:

```cpp fragment
auto texture = std::make_shared<windows::PixelTexture>(Size{320.0F, 180.0F});
texture->Publish({
    .pixel_width = 640,
    .pixel_height = 360,
    .bytes_per_row = 640 * 4,
    .format = windows::PixelFormat::Rgba8888,
    .pixels = pixels,
});
View preview = Image(texture).Fit(ImageFit::Contain);
```

`PixelTexture::Publish` copies required rows before returning, so this producer may reuse the source bytes. The input is straight-alpha untagged sRGB; the renderer receives its owned representation. Do not generalize this CPU-copy rule to all platform objects.

## GPU ownership matters

Windows D3D11 and Apple Metal publication create stable snapshots; serialize producer access as required by the concrete header. D3D11 needs a supported single-sampled BGRA source and matching graphics adapter, and is unavailable in Windows 7 compatibility builds.

Android/Linux `GlTexture::PublishCurrent` runs with the producer context current and publishes a stable copied snapshot. Linux `GdkTexture` instead retains an already immutable GDK texture: the application must not mutate its backing content afterward. Web publication follows the browser event-loop and VideoFrame lifetime contract.

Keep device/context loss, fences, and platform handles out of shared UI code. A module can expose a typed producer while owning the platform-specific work.

## Acquire a published frame

The platform producers listed below expose `AcquireFrame()` for external processing of the latest completed publication. Image and other consumers acquire independently. Retain the frame or imported resource until GPU use finishes. A subsequent publication, `Finish()`, or producer destruction leaves an acquired frame usable while its device and context remain valid. Treat the pixels as read-only and write processed output to a separate resource.

| Producer | Acquisition and lifetime |
| --- | --- |
| Android `GlTexture`, `SurfaceStreamTexture` | A shared `GlFrame` owns a premultiplied frame with bottom-left origin. `ImportCurrent()` imports a caller-owned `GL_TEXTURE_2D` in a compatible current OpenGL ES context on the same `EGLDisplay`. Delete the imported texture after GPU use. |
| Windows `D3D11Texture` | A shared `D3D11Frame` owns the snapshot. `TryCopyTo(context, destination)` submits a copy to a matching BGRA8 texture on the same adapter. Serialize immediate-context use and keep both resources alive until the copy finishes. A busy frame returns false. |
| Linux `GdkTexture`, `GlTexture` | A shared `GdkFrame` owns the retained GDK texture. `Texture()` and `TextureOrigin()` expose the borrowed resource and orientation. A GL frame can also borrow its texture name through `GlTextureNameCurrent()` in a compatible current `GdkGLContext`. |
| iOS and macOS `PixelBufferTexture` | A retained `CVPixelBufferRef`. Release it with `CVPixelBufferRelease` after CPU and GPU consumers finish. The producer keeps its pixels immutable while consumers retain it. |
| iOS and macOS `MetalTexture` | In Objective-C++, `AcquireFrame(origin)` returns the retained texture and its origin together. Sample on the owning Metal device. ARC manages the reference, or balance it with `release` without ARC. |
| Web `VideoFrameTexture` | A separate VideoFrame clone on the browser main thread. Before publication it returns `undefined` and a failed clone returns `null`. Close a valid clone on that thread after GPU use. |

Before the first publication, the platform result is empty. Follow the concrete header for context, format, and synchronization requirements. The [ExternalTexture Web example](/examples/external_texture/) demonstrates publication into Image.

## Separate layout from frames

Intrinsic size is set once in logical DIPs. The published pixel dimensions may change without changing that layout intent. Replace the texture identity if logical size really changes.

Publication schedules repaint without recomposition or paint-sequence rerecording. `IsActive()` helps avoid unnecessary production, but it is not an unmount callback. Stop work explicitly in your service/lifecycle cleanup, then call `Finish()`; the last published frame remains available to consumers.

## Verify on the actual backend

Test first publication, empty producer, changing frame resolution, hidden consumers, replacement, unmount, shutdown, context/device loss, and publication from the documented thread. A shared-header compile is not GPU or device validation.

Use [PlatformView](/docs/guides/platform-view/) instead when the embedded object must own platform-control interaction. See the [platform-specific reference](/docs/reference/platform-specific/) for includes.
